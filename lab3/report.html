1. Цель работы

Создать на своём сайте страницу авторизации, которая:

  • принимает данные формы методом POST и использует GET-параметры для навигации и сообщений;
  • сохраняет состояние входа и «запомненный» логин в cookie;
  • проверяет введённые данные (валидация) на стороне клиента (JavaScript) и сервера (PHP).

2. Теория

GET и POST

GETPOST
Где передаются данныеВ строке URL: ?tab=cookiesВ теле HTTP-запроса
ВидимостьВидны в адресной строке, истории, логахНе видны в URL
НазначениеПолучение данных, без изменения состоянияОтправка данных, изменение состояния (вход, выход)
В PHP$_GET$_POST
В лабораторнойПоказ формы, ?logout=1, ?error=auth, ?username=, вкладки ?tab=Отправка логина и пароля, выход (logout.php)

Пароль никогда не передаётся через GET, иначе он попадёт в историю браузера и логи сервера.

Cookie

Cookie — небольшие данные, которые сервер передаёт браузеру заголовком Set-Cookie, а браузер возвращает их в каждом следующем запросе заголовком Cookie. В PHP cookie устанавливаются функцией setcookie() и читаются из $_COOKIE.

CookieЗначениеСрокЗачем
auth_userлогин|HMAC-подписьДо закрытия браузераПризнак входа. Подпись не даёт подделать cookie вручную.
remember_loginлогин7 днейАвтозаполнение поля «Имя пользователя» (галочка «Запомнить меня»).
last_visitдата и время входа7 днейПоказывается на странице после входа.

Все cookie ставятся с флагами HttpOnly (недоступны из JavaScript) и SameSite=Lax (защита от CSRF).

Валидация

Клиентская (JavaScript) — даёт мгновенную подсказку, но её легко обойти. Серверная (PHP) — обязательна, потому что именно она защищает приложение. В работе используются одинаковые правила на обеих сторонах:

  • Имя пользователя: обязательно, 3–20 символов, только a–z A–Z 0–9 _ .
  • Пароль: обязателен, 6–32 символа, минимум одна буква и одна цифра.
  • После проверки формата — сравнение с хешем пароля через password_verify().

4. Реализация

4.1 Обработка GET и POST (login.php)

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $username = trim((string)($_POST['username'] ?? ''));
    $password = (string)($_POST['password'] ?? '');
    $remember = isset($_POST['remember']);

    $errors = validate_login($username, $password);

    if (!$errors) {
        $hash = USERS[$username] ?? null;
        if ($hash === null || !password_verify($password, $hash)) {
            $errors['form'] = 'Неверное имя пользователя или пароль.';
        }
    }

    if (!$errors) {
        set_app_cookie(AUTH_COOKIE, sign_user($username));
        set_app_cookie(VISIT_COOKIE, date('d.m.Y H:i:s'), time() + REMEMBER_TTL);
        $remember
            ? set_app_cookie(REMEMBER_COOKIE, $username, time() + REMEMBER_TTL)
            : delete_app_cookie(REMEMBER_COOKIE);

        redirect('welcome.php?tab=profile');   // Post/Redirect/Get
    }
} else {
    // GET: автозаполнение логина из ?username= или из cookie
    $username = trim((string)($_GET['username'] ?? ($_COOKIE[REMEMBER_COOKIE] ?? '')));
    if (isset($_GET['logout']))              $notice = 'Вы вышли из аккаунта.';
    elseif (($_GET['error'] ?? '') === 'auth') $notice = 'Сначала войдите в аккаунт.';
}

После успешного POST выполняется перенаправление (шаблон Post/Redirect/Get), поэтому обновление страницы не отправляет форму повторно.

4.2 Установка cookie (config.php)

function set_app_cookie(string $name, string $value, int $expires = 0): void
{
    setcookie($name, $value, [
        'expires'  => $expires,
        'path'     => '/',
        'httponly' => true,
        'samesite' => 'Lax',
        'secure'   => !empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off',
    ]);
}

function sign_user(string $username): string
{
    return $username . '|' . hash_hmac('sha256', $username, COOKIE_SECRET);
}

function current_user(): ?string
{
    $raw = $_COOKIE[AUTH_COOKIE] ?? '';
    if (!is_string($raw) || !str_contains($raw, '|')) return null;
    [$username, $signature] = explode('|', $raw, 2);
    $expected = hash_hmac('sha256', $username, COOKIE_SECRET);
    if (!hash_equals($expected, $signature) || !isset(USERS[$username])) return null;
    return $username;
}

4.3 Серверная валидация (config.php)

function validate_login(string $username, string $password): array
{
    $errors = [];
    if ($username === '') {
        $errors['username'] = 'Введите имя пользователя.';
    } elseif (mb_strlen($username) < 3 || mb_strlen($username) > 20) {
        $errors['username'] = 'Имя пользователя должно быть от 3 до 20 символов.';
    } elseif (!preg_match('/^[a-zA-Z0-9_.]+$/', $username)) {
        $errors['username'] = 'Допустимы только латинские буквы, цифры, «_» и «.».';
    }

    if ($password === '') {
        $errors['password'] = 'Введите пароль.';
    } elseif (mb_strlen($password) < 6 || mb_strlen($password) > 32) {
        $errors['password'] = 'Пароль должен быть от 6 до 32 символов.';
    } elseif (!preg_match('/[A-Za-z]/', $password) || !preg_match('/\d/', $password)) {
        $errors['password'] = 'Пароль должен содержать хотя бы одну букву и одну цифру.';
    }
    return $errors;
}

form.addEventListener('submit', (event) => {

if (!array_key_exists($tab, $tabs)) {
    $tab = 'profile';
}

4.6 Безопасность

  • Пароль хранится только как хеш (password_hash / password_verify).
  • Весь вывод экранируется функцией htmlspecialchars (защита от XSS).
  • Auth-cookie подписана HMAC-SHA256, сравнение через hash_equals.
  • Выход выполняется только POST-запросом; GET на logout.php возвращает 405.
  • При неверном логине или пароле выводится общее сообщение, чтобы нельзя было узнать, какие логины существуют.

7. Как запустить

Страницы входа написаны на PHP, поэтому нужен сервер с PHP (≥ 8.0). Локально:

cd web_labs
php -S localhost:8000
# открыть http://localhost:8000/lab3/login.php
# демо-аккаунт: dinmukhamad / Lab3pass
GitHub Pages отдаёт только статические файлы и не выполняет PHP, поэтому на GitHub Pages открывается этот отчёт, а сама форма входа работает на сервере с PHP (локально через php -S или на любом PHP-хостинге).

8. Вывод

В ходе работы была создана страница авторизации для сайта. Разобрана разница между методами GET и POST: GET используется для получения страниц и передачи неконфиденциальных параметров (сообщения, вкладки), POST — для отправки логина и пароля и для выхода. Состояние входа хранится в подписанной cookie, а функция «Запомнить меня» реализована через cookie со сроком жизни 7 дней. Введённые данные проверяются дважды: в браузере (JavaScript) для удобства пользователя и на сервере (PHP) для безопасности. Все 12 тестовых сценариев пройдены.

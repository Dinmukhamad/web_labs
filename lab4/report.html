1. Цель работы

Доработать вход из Lab 3: добавить регистрацию, хранить пользователей в базе данных и оформить страницы с помощью CSS-фреймворка.

  • Database — пользователи и сессии хранятся в SQL-базе данных SQLite;
  • Registration — форма регистрации с проверкой полей и уникальности логина и email;
  • Login — вход по имени пользователя или email, сессия в cookie, выход;
  • Framework — интерфейс на Bootstrap 5;
  • сайт остаётся на GitHub Pages — без серверного кода.

3. Как работает сайт

  1. Сайт открывается со страницы входа index.html. При первом открытии создаётся база данных с таблицами и демо-пользователем.
  2. Новый пользователь нажимает «Зарегистрироваться» (register.html), заполняет форму, данные проверяются и записываются в таблицу users.
  3. После регистрации открывается index.html?registered=1&login=…: сообщение «Аккаунт создан», логин уже подставлен.
  4. При входе пароль сверяется с хешем из базы, создаётся запись в sessions, а токен сохраняется в cookie.
  5. Открывается страница Instagram profile.html с данными пользователя из базы. Без действующей сессии она перенаправляет на index.html?error=auth.
  6. Страница lab4/database.html показывает содержимое таблиц и содержит SQL-консоль.
  7. «Выйти» удаляет сессию из базы и cookie и открывает index.html?logout=1.

4. База данных

4.1 Схема

CREATE TABLE users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    full_name     TEXT    NOT NULL CHECK (length(full_name) BETWEEN 2 AND 50),
    username      TEXT    NOT NULL UNIQUE COLLATE NOCASE
                          CHECK (length(username) BETWEEN 3 AND 20),
    email         TEXT    NOT NULL UNIQUE COLLATE NOCASE CHECK (email LIKE '%_@_%._%'),
    password_hash TEXT    NOT NULL,
    salt          TEXT    NOT NULL,
    created_at    TEXT    NOT NULL DEFAULT (datetime('now')),
    last_login    TEXT
);

CREATE TABLE sessions (
    token      TEXT    PRIMARY KEY,
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TEXT    NOT NULL DEFAULT (datetime('now')),
    expires_at TEXT    NOT NULL
);
СвязьОписание
users 1 — N sessionsУ пользователя может быть несколько сессий (разные браузеры или вкладки). При удалении пользователя его сессии удаляются (ON DELETE CASCADE).

COLLATE NOCASE делает логин и email нечувствительными к регистру: Dinmukhamad и dinmukhamad считаются одним логином.

4.3 Запросы только с параметрами

function query(sql, params = []) {
    const stmt = db.prepare(sql);
    try {
        stmt.bind(params);                      // значения подставляет SQLite
        const rows = [];
        while (stmt.step()) rows.push(stmt.getAsObject());
        return rows;
    } finally {
        stmt.free();
    }
}

Пароль хешируется функцией PBKDF2 (100 000 итераций SHA-256) с уникальной случайной солью:

async function hashPassword(password, saltHex) {
    const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(password), 'PBKDF2', false, ['deriveBits']);
    const bits = await crypto.subtle.deriveBits(
        { name: 'PBKDF2', hash: 'SHA-256', salt, iterations: 100000 }, key, 256);
    return toHex(bits);
}

6. Вход, сессии и cookie

async function login(loginValue, password, remember) {
    const [user] = Db.query('SELECT id, password_hash, salt FROM users WHERE username = ? OR email = ?', [login, login]);
    if (!user || (await hashPassword(password, user.salt)) !== user.password_hash) {
        return { ok: false, errors: { form: 'Неверное имя пользователя, email или пароль.' } };
    }
    const token = randomHex(32);                                   // 256 бит случайности
    Db.run("INSERT INTO sessions (token, user_id, expires_at) VALUES (?, ?, datetime('now', ?))",
           [token, user.id, remember ? '+7 days' : '+1 day']);
    Db.run("UPDATE users SET last_login = datetime('now') WHERE id = ?", [user.id]);
    await Db.save();
    setCookie('lab4_session', token, remember ? 7 * 24 * 60 * 60 : undefined);
    return { ok: true, errors: {} };
}

async function currentUser() {                 // кто вошёл — по токену из cookie
    const [user] = Db.query(
        `SELECT u.* FROM sessions s JOIN users u ON u.id = s.user_id
         WHERE s.token = ? AND s.expires_at > datetime('now')`, [getCookie('lab4_session')]);
    return user ?? null;
}

11. Скриншоты

12. Вывод

В ходе работы на сайт добавлены регистрация и вход с хранением данных в базе SQLite. База создаётся и работает прямо в браузере (sql.js, WebAssembly) и сохраняется в IndexedDB, поэтому сайт продолжает работать на GitHub Pages без сервера. Таблица users хранит пользователей с хешем пароля (PBKDF2 с солью), таблица sessions — активные сессии; в cookie записывается только случайный токен. Все запросы параметризованы, что защищает от SQL-инъекций. Данные проверяются на трёх уровнях: в форме, в логике регистрации и ограничениями самой базы (UNIQUE, CHECK). Интерфейс оформлен с помощью фреймворка Bootstrap 5: карточки, плавающие поля, стили валидации, таблицы, навигация и модальное окно. Все 37 тестовых сценариев пройдены.

Ограничение: база хранится в браузере каждого посетителя отдельно. Для общей базы между всеми пользователями нужен сервер или облачная база данных (например, Supabase или Firebase).
